# Troubleshooting

## `npm` is blocked in PowerShell

Symptom:

```text
npm.ps1 cannot be loaded because running scripts is disabled on this system
```

Fix: use `npm.cmd` instead of `npm` on this host. Do not change the system execution policy unless you explicitly want to.

```powershell
npm.cmd install
npm.cmd run dev
```

## MongoDB is not reachable

Check the service:

```powershell
Get-Service MongoDB
```

Check the health endpoint or run:

```powershell
npm.cmd run check:mongo
```

MongoDB must listen on `127.0.0.1:27017`. Do not change it to `0.0.0.0`.

Current environment note: PATH points at a missing MongoDB 8.0 directory. Use the Windows service or the absolute path under `C:\Program Files\MongoDB\Server\9.0\bin`.

## API starts in degraded mode

The API intentionally starts even when MongoDB is unavailable so the health endpoint can report the problem. Start MongoDB, then restart the API or wait for reconnection.

## Port 4000 or 5173 already in use

Find the process:

```powershell
Get-NetTCPConnection -LocalPort 4000,5173 -State Listen
```

Stop the conflicting process or change `PORT` / the Vite port temporarily. Do not expose the development server to other devices.

## A Settings panel appears twice after refresh

The development server no longer registers an app-shell service worker. Earlier dev builds did, and a cached shell could mix old and new UI chunks, which duplicated the **Offline and sync** or **App update** cards.

Each dev page load now unregisters stale development service workers and clears Cache Storage for that origin. If you still see a duplicate, close the tab, run `npm.cmd run dev`, and open `http://127.0.0.1:5173` again. This clears only cached app files; records, settings, and the encrypted offline queue are untouched.

## Vite build fails on the generated route tree

The route tree is generated by TanStack Router. This project uses `disableTypes: true` and a `.js` output. If the generated file is stale or corrupted, delete `src/client/routeTree.gen.js` and run:

```powershell
npm.cmd run build
```

Do not edit the generated file manually.

## Lint warnings

Warnings about Fast Refresh in route or UI files are configured off for those paths. `npm.cmd run lint` should exit successfully with no errors or warnings. If it does not, fix the issue rather than ignoring it.

## Screenshot or learning attachment upload fails

- Use JPEG, PNG, or WebP only. The file contents must be a real image, not just a matching extension.
- Each image must be 10 MB or smaller.
- A trade can have at most five active screenshots; a learning record can have at most five active attachments. Delete one before adding another.
- Bytes are stored under `storage/uploads` and delivered only through authenticated file URLs. Reload the page if its session expired.
- Learning attachments can only be added to an active owner-scoped record. Restore a deleted record first.

## Local network access does not work

LAN access is not configured yet. Future setup requires:

- Private Windows network profile.
- Firewall rule for TCP 443 on Private/LocalSubnet.
- Trusted local HTTPS certificate.
- Express bound to the LAN interface.
- Router client isolation disabled.

Do not open MongoDB or the Vite development server to the LAN.

## The app shows “The API is unreachable”

The client could not reach the local API. Confirm the API is running, then select **Try again**. Check the API console for Pino errors and run `npm.cmd run check:mongo`.

## I open a page and do not see a form

Trading Setup, Analytics, Learning, and Daily Journal intentionally open in view or analytics mode. Use the section action such as **Open calculator**, **Add account**, **Add adjustment**, **Add category**, **New record**, **New goal**, **Write today’s entry**, or **Add note** to reveal the form. Fields that are not needed for the first pass are behind **Show optional fields**.

The Calendar is no longer linked from the desktop sidebar or mobile header. It still opens at `/calendar` if you navigate to that address directly.

## A trade detail, Learning, Daily Journal, Dashboard, or Calendar page does not open

Rebuild the client to regenerate the TanStack route tree, then reload:

```powershell
npm.cmd run build
```

Do not edit `src/client/routeTree.gen.js` manually.

## A journal entry or note cannot be saved

- Confirm the date is a real `YYYY-MM-DD` date. Dates use the app time zone in Settings.
- Only one active entry is allowed per date. Edit the existing entry, or delete it before creating another.
- Mood must be between 1 and 5 or left unset; gratitude allows at most three items and tomorrow's priorities at most five.
- If another tab changed the record, reload and retry the save. Stale writes return a version conflict instead of overwriting.

## A journal reminder does not appear

- Reminders are local UI notices shown only on the Daily Journal page while the app is open.
- Enable the reminder and set a 24-hour time in Settings, then save preferences.
- The banner appears only after the reminder time and only when today's entry is missing. It can be dismissed for the current visit.

## A dashboard layout will not save

- Layout names must be 1–60 characters and unique for this owner.
- Widget IDs must be `trades_summary`, `study_summary`, `calendar_activity`, or `goals_progress`. Sizes are `small`, `medium`, or `large`; positions must be integers from 0 to 50.
- The trading widget accepts `basis` of `gross` or `net`, and the trading and study widgets accept `days` from 7 to 365.
- If another tab changed the layout, reload and retry. Stale writes return a version conflict instead of overwriting the newer layout.
- The current default layout cannot be deleted. Set another layout as default first.

## The calendar shows no journal marker

- The **Calendar journal marker** setting is off by default. Enable it in Settings and save preferences.
- A marker appears only for dates with an active journal entry owned by you. It is a neutral dot; no journal content, mood, gratitude, notes, priorities, or attachments are shown.
- Net P&L stays **Unavailable** on empty days and on days where a trade has no recorded fees.

## A poster will not save or export

- Poster names must be 1–80 characters and unique for this owner.
- The type must be `trading`, `learning`, or `trade`; templates are `midnight`, `paper`, or `ember`; sizes are `square`, `portrait`, or `story`.
- The accent color must be a `#RRGGBB` hex value, and the period must be between 7 and 365 days.
- A **Single trade ROI** poster requires one of your active completed trades. If none appear, record and complete a trade first. An unknown or foreign trade cannot be used.
- ROI on risk stays **Unavailable** when the selected trade has no valid risk value. Net P&L and net ROI also stay unavailable when fees are missing.
- If another tab changed the poster, reload and retry. Stale writes return a version conflict instead of overwriting the newer design.
- PNG export uses the browser canvas. If it fails, try Chrome or Edge and make sure the live preview has finished rendering. Export never uploads the image.

## Setup says the owner account already exists

Only one owner can be created. The setup screen appears only when no owner exists. Sign in with the existing account. If the owner password is lost, a local administrator recovery command will be added in a later phase; the first release does not expose a remote reset.

## The app opens offline or the cache is locked

- Offline access works only after a successful sign-in or onboarding on that browser has prepared the local verifier and encrypted cache.
- Start the local server if you expected it to be available. The app checks the local API on boot.
- Open **Settings → Offline and sync** and enter the owner password used when the cache was prepared. The local verifier is separate from server authentication and is never sent to the server.
- If the password was changed on another browser, sign in once online on this browser to refresh the local verifier.
- Only previously cached, allowlisted records are available offline. Authentication, settings, security, and finance data are never persisted locally.

## Changes stay Pending, Conflict, or Blocked

- **Pending** means the server has not confirmed the change. In **Settings → Offline and sync**, reconnect and wait for automatic replay, or select **Sync now**.
- **Conflict** means the server record changed after it was loaded. Your local payload is kept in Settings until you choose **Keep server**, **Use mine**, **Merge manually**, or **Discard**.
- **Blocked** means the server rejected the request for validation, authentication, or ownership reasons. Read the message in Settings and correct the record.
- Duplicate replay is safe: the client sends the same `Idempotency-Key`, and the server returns the stored response instead of applying the change twice.
- Browser storage quota failures appear explicitly. Pending work is not deleted; free browser storage or remove large local site data before retrying.
- Open **Settings → App update**. Select **Check for updates** to ask the local service worker for a newer shell; if one is ready, select **Update now** to activate it.

## Requests fail with “The request could not be verified”

The CSRF cookie and header no longer match, or the browser sent a foreign `Origin`. Reload the page to obtain a fresh token. Do not disable CSRF protection.

## I was signed out unexpectedly

- Sessions expire after 7 days of inactivity.
- Changing the password signs out all other sessions.
- The workspace auto-locks after 15 minutes; unlocking does not sign you out.

## Tests fail with `MongoServerSelectionError`

Integration tests require local MongoDB. Run `npm.cmd run check:mongo`. Tests use the separate `ys_journal_test` database and never modify `ys_journal`.

## Where are logs?

API output goes to the console in JSON through Pino, with cookies, tokens, and passwords redacted. Persistent service logs arrive with the Windows service in Phase 13.

## Where is my data?

Owner setup creates `users`, `sessions`, `settings`, `security_events`, and `app_meta`. Opening **Trading setup** also creates `instruments`, `trading_accounts`, `tags`, `trading_sessions`, and `checklist_items`. Recording a trade creates `trades` records and, when screenshots are attached, `files` metadata plus bytes under `storage/uploads`. Learning data is created only when you add a category, record, or goal yourself. Opening the Dashboard ensures a `dashboard_layouts` default layout exists; calendar totals are derived on request and are not stored. No learning records, personal journal entries, or sample data are created automatically.

## I cannot archive the default account

Set another active account as default first. Exactly one active account must remain default. The original `Main Account` can be renamed and edited.

## The calculator or a trade shows Unavailable

Missing fees, missing risk, or invalid stop placement leaves the dependent value unavailable by design. Enter actual fees and a valid initial stop or manual risk to see net P&L and R.
